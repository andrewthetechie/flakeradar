- **Pydantic's epoch rule (task 34).** Measured from the reference's own `pydantic` 2.14.2
  in `/tmp/pyref`, not inferred. A number whose magnitude is past `2e10` is a millisecond
  count (`20000000000` → `2603-10-11T11:33:20`, `20000000001` → `1970-08-20T11:33:20.001`,
  `1767225600000` → `2026-01-01T00:00:00`, `1767225600123` → `...00.123`, `253402300799` →
  `1978-01-11T21:31:40.799`, `1e14` → `5138-11-16T09:46:40`), a magnitude at or below it is
  seconds (`-20000000001` → `1969-05-14T12:26:39.999`), and a string holding a plain decimal
  number is the same instant (`"1767225600"`, `"1767225600.5"`, `"1767225600000"`,
  `"1700000000"`, `"0"`, `"-5"`), while `"1e3"`, `"1_000"` and `" 1767225600"` name no date.
  The years a datetime holds are 1 to 9999: `1e15`, `253402300800000` and `"253402300800000"`
  answer `datetime_parsing` with `dates after 9999 are not supported as unix timestamps` in
  both `msg` and `ctx.error`, `-62135596800001` answers `year 0 is out of range`, and
  `-62200000000000` answers `dates before 0000 are not supported as unix timestamps`. The
  command, verbatim:

  ```bash
  /tmp/pyref/bin/python - <<'EOF'
  from pydantic import BaseModel
  from datetime import datetime
  class M(BaseModel):
      t: datetime | None = None
  for v in [20000000000, 20000000001, -20000000001, 1767225600000, 1767225600123,
            253402300799, 253402300800, 1e14, 1e15, 253402300800000, -62135596800001,
            "1767225600", "1767225600.5", "1767225600000", "1700000000", "0", "-5",
            "1e3", "1_000", " 1767225600"]:
      try:
          print(repr(v), M(t=v).t)
      except Exception as e:
          print(repr(v), [l.strip() for l in str(e).splitlines() if "type=" in l])
  EOF
  ```
